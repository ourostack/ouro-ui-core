# Ouro UI core

Core is the platform-neutral part of Ouro UI: what is true on every platform, for Ouro HX (people) and Ouro AX (agents). Today it holds the tokens and their generators, and the decision records. The HX design language, AX's claims standard and the ui.ouro.bot site arrive later. Platform code lives in its platform's repository: web in `ourostack/ouro-ui`, Apple in `ourostack/ouro-ui-apple`.

## Tokens

- `tokens/` is the source. `dist/` is generated by `pnpm tokens`; never edit it, and it is not committed.
- `templates/web/` holds web's stylesheets with a placeholder per value. Change a template only for prose or non-token CSS.
- `pnpm tokens:parity` must pass: `dist/web/` equals web's files at `parity.json`'s `webTag`, byte for byte. A token change lands in web first, then here with a `webTag` bump, until web builds from core.
- Before you push, run `pnpm typecheck`, `pnpm tokens`, `pnpm tokens:parity`, `pnpm test`, and on a Mac, `pnpm apple:check`.

## Claims

A factual sentence is a claim on every surface: Markdown, code comments, a pull request's title and body. Give each claim its primary source (a file, a test, a command's output or a link) and, where one exists, the check that proves it, so the next agent can trust it without rebuilding the proof. Don't reword a claim to get past review: source it, correct it, or remove it. This is web's Claims rule; its `pnpm claims:lint` tooling moves here with the standard.

## Look around first

Meerkat mode: look around first. Before you design or build something new (a component, a kit, a standard, a tool or a platform target), look for prior art to adopt or borrow, and do it again for every decision record: give the record a "Prior art" section that links each find and marks it adopt, borrow, watch or ignore (Ari, 2026-11-03: "make it a standing rule for all the ouro ui stuff!!").

## Working here

- Every change after the initial import goes through a pull request, merged when CI is green.
- Releases are tags `vX.Y.Z` matching `package.json`'s version; the release workflow attaches `dist/` to the GitHub release.
- Other agents work in web and the platform repositories. Copy first, remove later, and never rebase or force-push someone else's branch.
